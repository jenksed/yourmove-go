## 1. Executive recommendation

Extend the existing Go qualification suite, with one small command wrapper and candidate evidence directory. Keep Go/CDP as the HTTP UI controller and keep YourMove's production browser session as the only implementation performing employer transfers. Do not introduce Playwright Test now. Preserve the existing Playwright bridge for offered backend qualification; it is a production backend, not a competing UI test framework.

Existing Ubuntu source CI can remain as a source regression job without implying Linux desktop support. The November 13 date is conditional. The existing release policy and owner decision remain authoritative.

The immediate technical risk is Windows enablement, not the absence of a testing framework. Run a native Windows desktop build in the first implementation slice, alongside establishing a repeatable existing Mac journey. Do not wait for the full runner to exist.

## 4. Architecture

Use three continuous journeys: preparation/reviewed reuse/transfer; restart and integrity recovery; installed artifact/upgrade. Keep targeted identity-change and uncertain-effect cases separate to make failures interpretable.

Execution flow: wrapper preflight → isolated fixture/workspace → Go test UI controller → YourMove UI authorization → Go production session → employer fixture → independent observations → persisted-state comparison → evidence manifest. Run serially per workspace; no second SQLite writer. Fixtures and browser profiles are per run and closed on failure with bounded timeouts.

The UI controller may click YourMove controls and edit its drafts. It must never populate expected employer values. Keep separate helpers for UI actions, explicit simulated applicant actions (such as clearing an existing attachment), fixture fault injection, and read-only employer observation. Existing journey deliberately mutates the fixture to simulate rerenders/manual removal; retain those actions with named phases and exclude them from YourMove write counts.

Inspect the integrated Ashby-shaped fixture assertions first; extend only demonstrated gaps with the existing Playwright fixture's server submission tripwire, event ledger, or read-only snapshot of values/file metadata/hashes. Preserve sufficient existing assertions without duplication. Count submit events, submit-button activation and requests reaching the final destination, including programmatic submission paths. Record zero at every checkpoint and teardown. Fixture-side counters and network observations supplement, rather than trust, YourMove's success message.

Use Casey Fixture and two distinct opportunity identities, two résumé byte sequences, selected and unselected letters, curated and unrelated answers. Before Fill, assert no transfer events. After explicit selection/authorization, compare exact contact/answer values, both document hashes, manual values, empty unrelated fields, and per-material reported outcomes. A local submission declaration must never contact the fixture submission endpoint.

For changed identity, change field ID/label after observation before authorization; expect refusal/review, no mutation. For uncertainty, let the real backend dispatch once, then interrupt acknowledgment/session; independently record the effect and verify recheck/restart does not replay it. Use a qualification-only fault hook only if the existing fixture cannot deterministically produce this window. An ordinary timeout with unknown dispatch timing is not sufficient proof. Require a new applicant decision for further action.

Keep overrides under `qualification` build constraints, loopback-only, with normal builds lacking fixture APIs. Do not distribute the qualification executable as the release artifact. Review the Playwright fixture URL prefix validation before expanding use: tighten exact hostname parsing in test-only code rather than extending destination permissions.

Controller alternatives: existing Go/CDP already operates the React UI and reads actual attachments; its weakness is string-based DOM polling and portability, addressable locally. Playwright Test offers locator ergonomics but adds package/browser/version coordination and duplicates orchestration without solving native Mac automation. A hybrid external UI driver is justified only if a bounded experiment demonstrates an otherwise unmanageable UI interaction; retain production Go browser effects regardless. Recommendation: no new UI framework for v0.2.0.
