# Early-tester feedback

YourMove is being built with real job seekers as the intended users. We are looking for concrete friction: the step that made you stop, the field that did not behave as expected, and the thing you had to do outside the app to finish.

**You do not need a technical background to give useful feedback.** Testing the first three steps is enough.

## Pick one

- [Share how it felt to use YourMove](https://github.com/jenksed/yourmove-go/issues/new?template=experience-feedback.md): confusing language, missing steps, unclear controls, or anything that slowed you down.
- [Report a reproducible problem](https://github.com/jenksed/yourmove-go/issues/new?template=bug-report.md): something broke, did the wrong thing, or failed to preserve your work.
- [Read existing issues](https://github.com/jenksed/yourmove-go/issues): check whether somebody has already reported the same problem, and add a comment if you have additional evidence.

Opening a GitHub issue requires a GitHub account. If you cannot use GitHub, public launch-post replies can still provide useful general feedback, but do not publish personal application information.

## The most valuable trial

Use [the local preview guide](TRY_IT.md), then try this path:

1. Save an actual job posting.
2. Review the imported details and correct anything inaccurate.
3. Import a resume and select it for that job.
4. Read the preparation workflow. Can you tell what is safe to do next?
5. If you are comfortable, open the employer application and tell us where YourMove helps or gets in the way.

There is no requirement to send a live application just to test this software. Do not submit an application as part of a bug reproduction unless it is one you independently intended to send.

## Tell us what happened

The most actionable report includes **what you were trying to do**, **what you expected**, **what happened instead**, and **whether you could continue**. When useful, include macOS or other OS version, native Wails vs local browser, app commit or build version, browser version, and application platform (Ashby, Greenhouse, Lever, etc.).

If you're unsure which part failed, just describe the last thing you clicked and what you saw.

**Privacy:** Do not post your resume, name, address, email, phone, job-application answers, cookies, tokens, credentials, or employer-form data. Crop or redact screenshots and logs. Prefer platform names over private application links. Developers may ask for a minimal reproduction that uses synthetic information.

## What we will prioritize

Early feedback is most useful when it helps someone complete a real application-preparation step. Clear navigation, correct resume selection, handoff continuity, recognizable failure messages, and accurate boundaries matter more than elaborate feature requests. Nothing in this document promises a response time or a fix in a particular release.
