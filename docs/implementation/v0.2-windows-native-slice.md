# v0.2 Windows native first slice — implementation handoff

Branch: `v0.2/feat-windows-native` @ `5e18147` (4 commits on top of `b5e3a46`).
Host: macOS 26 arm64, Go 1.27.3. No Windows 11 graphical host was available:
Checkpoints A and B are IMPLEMENTED and VERIFIED; C and D are NOT RUN.

## Implemented behavior

1. **Shared dependency baseline** — Wails `v3.1.0` (exact pin), Go `1.27.3`.
   No application code changes were needed; both suites pass and the macOS
   desktop binary builds clean.
2. **Windows desktop entry point** — `desktop_windows.go`
   (`desktop && windows && !qualification`) reuses the new shared composition
   in `desktop_shared.go`, so Windows launches the same Go app, routes, asset
   handler, native dialogs, and SQLite workspace as macOS. `desktop.go` is now
   a thin macOS main; `desktop_probe.go` covers both OSes. No duplicate or
   missing entry points; Linux `desktop` builds behave exactly as before.
3. **Bounded browser-discovery repair** — new `browser.IsExecutableFile`
   keeps the Unix execute-bit rule and accepts regular `.exe`/`.cmd`/`.bat`/`.com`
   files on Windows, replacing the two helpers that rejected every Windows
   binary. Chromium resolution gains `chrome` LookPath names, ProgramFiles /
   LOCALAPPDATA install locations, the LOCALAPPDATA Playwright cache, and
   `chrome-win64` / `chrome-win` / `chrome-linux` cache suffixes. The Playwright
   bridge gains Windows Node candidates and win64 / `firefox.exe` engine
   patterns. Unix/macOS paths and explicit overrides are unchanged.
4. **CI** — new `windows-2025` compile-verification job (frontend build, vet,
   native `desktop`-tagged `.exe` build, provenance record); Ubuntu job gains
   a `windows/amd64` cross-compile step. Triggers extended to `v0.2/develop`;
   `main` protections and existing jobs unchanged. Compile-only by design.
