## 7. Security and authority assessment

Code-reviewed paths (`writingSaveAPI`, `writingSaveEarly`, starting-point,
both promotion handlers, browse, letter manual/save/select/history/catalog/detail,
reconciliation accept, `persistApplicationAnswer`):

- Exact vs related: separate `reusable` opt-in (revision-checked memory update) vs
  ordinary save vs explicit library promotion. Related use never writes memory or
  the library; the origin snapshot is display metadata — `resolveApplicationAnswer`
  and all transfer/fill paths never read `reuse_source_json`.
- Source/destination validation: destination must equal the saved job URL; question
  key + saved revision re-resolved from current inspections; entry existence +
  revision rechecked at use and at save; library promotion revalidates the saved
  revision transactionally; early promotion validates discovery identity + saved
  revision in one transaction with a distinct dedup namespace.
- Unsaved work: React pins the baseline revision and guards question switches and
  source replacement (Replace/Keep); server conflicts retain the draft and never
  auto-retry; letter save uses content-hash compare-and-save; letter preview and
  catalog detail perform no writes and never change selection.
- Completed/closed applications: all write endpoints refuse with conflict; catalog
  and content reads stay read-only.
- New identities: prior-letter reuse INSERTs a fresh `manual` row with NULL résumé
  sources (no AI/evidence inheritance) and server-built origin; selection updates
  atomically with the insert under the editability guard.
- No silent operations found: overwrites require revision match; replacement requires
  explicit confirmation; selection changes only via the select endpoint; related
  writing gains no exact approval; old résumé/AI authority never transfers to manual
  copies; no path transmits application material to an employer (Submit remains the
  local manual-declaration endpoint, untouched).

One contract gap found and fixed: reconciliation accept dropped the early origin
instead of carrying it (`c1466fa`, tested). No authority impact — origin was and
remains display-only.
