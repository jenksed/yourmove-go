# Incremental implementation roadmap

Every increment: isolated branch → one coherent change → controlled real-path checks → actual Wails captures → owner review → revise/approve → merge into main → verify CI. Do not accumulate approved changes indefinitely on feature branches. No increment is implemented here.

## First increment acceptance brief

Keep the native title bar and current default/minimum outer sizes. Change only the shell and Opportunities composition. All eight destinations remain named; compact navigation cannot require icon recognition. Keep the Add/import POSTs, bulk deletion confirmations, stage/priority ordering, suggested-next semantics, and progress arithmetic. The prototype's synthetic content is never copied into production templates.

Acceptance screenshots use identical fixtures, theme, viewport and scroll origin. Record native **outer bounds and `window.innerWidth/innerHeight` separately**. At 900×700 target, job rows should become visible sooner without clipping filters or burying Add. At minimum, every required control remains reachable with one primary document scroll. Measure before declaring improvement; do not set a row-count target that encourages truncating meaningful titles.

## Deliberately deferred engineering

Durable unsaved drafts, automatic browser restoration, full submission packet snapshots, manual creation of a first cover letter, global command palette, native Quick Look, model discovery, credential storage, window-state persistence, and generalized component frameworks are not prerequisites for this direction. Some are valuable later, but each needs an independent backend/native decision and acceptance plan. No cloud account or SaaS navigation work is proposed.
