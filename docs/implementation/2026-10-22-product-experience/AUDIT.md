## Evidence and limits

Source basis is the verified starting SHA. Read: README, CODEBASE_GUIDE, DESIGN_SYSTEM, RULES, Iteration 3.2 writing report, answer-assistance refinement, clipboard checkpoint 3, and release checklist. Inspected all 15 page templates, shared partials, CSS, relevant UI/polling JavaScript, Wails bootstrap/probe, route registration, continuation, browser session, AI ticket/generation, provider-readiness, letter persistence, and schema. Prior reports are historical evidence, not new acceptance results. Current native interaction remains unqualified.

Severity: **S1** could mislead about state or lose work; **S2** repeatedly slows a core task; **S3** weak hierarchy or secondary friction. These are expert inspection judgments, not measured user failure rates. Complexity: L = scoped template/CSS; M = coordinated templates/JS/view data; H = new persistence or native behavior. No finding below establishes an exploitable backend defect.

## State contract

| State | Honest display / recovery |
|---|---|
| No jobs / first job / large list | Focused empty CTA; first row immediately useful; filters and ordering stay accessible. No automatic import or hidden pagination promise. |
| Selected resume valid / missing | Selected locally / choose available document. File availability and employer acceptance are different. |
| Profile approved / incomplete | Approved by you / save draft or approve. Incomplete optional fields do not block unrelated work. |
| No questions / many / prepared | Not discovered / selector plus counts / saved locally. Zero discovered is not “nothing left to do.” |
| Missing AI / generating / proposal | Continue manually / named progress / not saved, review claims. Generation errors preserve saved writing. |
| No letter / saved letter | Optional generation path with prerequisites / editor first even if old sources are unavailable. |
| Browser active / interrupted / another job | Work in existing browser / restart caveat / return to owning job. |
| Partially successful transfer | Per-item outcomes. Preserve successes, expose uncertainties and manual work; no blanket green completion. |
| Manually submitted / locally recorded | User confirms on employer site / timestamped local record. YourMove cannot independently detect receipt. |
| Restart | Durable materials available; browser-only state not restored; source reviews may need renewal. |

## Backend contracts that constrain design

`application_continuation.go` executes resume/contact, letter, and answer commands independently; a failure does not roll back successful items. It excludes already attempted answers and handles other active jobs. `browser_session.go` owns transient runtime state. `nextApplication` requires recorded completion before retiring the current browser. Neither navigation nor saving may impersonate these commands.

`application_answer_ai_state.go` holds up to 16 review tickets in memory, initially expiring after ten minutes; completed generation extends expiry. `ui.js` can retain bounded previews in sessionStorage, which is not durable workspace storage. The UI must not imply AI previews survive application restart. Previous-writing insertion is unsaved, library snapshots are independent, and reviewed evidence is applicant review only.

`ai_handlers.go` describes runtime configuration without rendering keys or initiating sign-in. Ollama is checked at generation. Cover-letter generation persists a new draft; editing preserves source identity. Submission records retain resume names/hashes. Wails POST redirects pass through `desktop_redirect.go`; new hash/query return variants require explicit compatibility review.
