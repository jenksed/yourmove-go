## 3. Six implementation slices

**Foundation/changes:** Keep the existing workspace activities and Go readiness decisions. In `WorkspacePage.tsx` present a compact selected-materials/unresolved-work overview and state-appropriate primary action. Derive missing information in `workspace_api.go` from existing Go assessment, not parallel React rules. Add searchable opportunity association in `ResumesPage.tsx` using existing opportunity API and current assignment writer. Keep explicit selection, archived/master document restrictions and exact file identity. Include collapsed Add Opportunity default: initial empty and populated lists closed; initial explicit hash and explicit Add actions open; refresh after intake preserves deliberate disclosure state. Check hash/navigation transitions, not just the initializer.

**Dependencies:** Existing transport contracts; no Wails update or schema migration required. Own workspace shell, résumé association UI and Opportunities disclosure. Coordinate WritingSection integration with S2.

**Acceptance:** Actual UI on two synthetic jobs: empty launch closed → Add → single and bulk intake unchanged; direct explicit Add navigation opens. Select/search another résumé, restart and verify ID/hash association. Zero-question job proceeds without invented writing work; existing chosen résumé never silently replaced. Record repeated choices and corrections against baseline. Keyboard operation and minimum-window primary path remain usable.

**Exclude:** Last-choice learning, new routing rules, onboarding/settings mechanism, whole workspace redesign.

**Dependencies:** Agree minimal workspace summary/refresh contract with S1. **Acceptance:** UI offers exact eligible, similar, and new questions; cross-employer identical text remains review-required. Explicit copy/adapt/save persists correct destination and revision, while changed options/identity cannot reuse old authorization. #### S2 retention addition — manage older letters without losing reusable work

Added at the owner's request: keep accumulated cover letters manageable and address device storage, while making older writing retrievable. This belongs with S2, not a separate infrastructure milestone.

**Storage finding:** `internal/storage/sqlite.go` stores letter bodies as SQLite TEXT; résumé sources are references/hashes, not copies embedded in every letter. `cover_letters.go:validLetterBody` caps a body at 12,000 bytes. Thus 1,000 maximum-sized letter bodies total approximately 12 MB before metadata, indexes, SQLite overhead and any other stored copies; this is an arithmetic illustration, not measured workspace usage. `listCoverLetters` currently shows only the latest 30 entries, which is a display limit, not a retention policy. Older letters must be reachable through pagination/search rather than becoming effectively hidden.

**Recommended commitment:** Add explicit Archive / Browse archived / Restore actions in the letter interface and prior-letter picker. Archive removes a letter from the ordinary active list but preserves its ID, exact text, dates, source references and history associations. Archived writing can be opened on demand and deliberately copied as a new current-job draft without restoring its old approval or authorizing transfer. Preserve existing selections: refuse archival of the currently effective selected letter until the applicant explicitly changes/clears that selection. Account for `selectedCoverLetter`'s legacy latest-draft fallback; changing list filters must never silently change which letter is selected. No automatic age-based expiry or deletion.

Provide explicit permanent deletion only for unused drafts, with a clear confirmation identifying the letter and irreversibility. Go must refuse deletion when selection, recorded history, or another durable association requires the letter; trace actual reference paths before implementing the predicate. Never delete user-exported files outside the managed workspace. Show letter count and logical text size separately from total workspace disk usage, so an archive action does not misleadingly promise reclaimed space. SQLite deletion can free reusable pages without immediately shrinking the database file; do not claim bytes returned to the OS without measuring them. Do not add routine VACUUM/startup compaction as part of this feature.

**Compression recommendation:** An archive is initially an organizational state in the existing database, not a ZIP file or a second store. Defer mandatory compression until a synthetic representative retained-letter corpus demonstrates worthwhile net disk savings. This avoids a new failure-prone archive extraction path for already-small text records. Measure total database/file allocation before and after a compression prototype, including metadata and temporary space, rather than only compressed string lengths. If savings justify a later implementation, prefer versioned compressed bodies inside the same SQLite transaction/identity model, decoded on demand through the authoritative Go reader; preserve readable metadata and bound decompression size. Do not retain duplicate authoritative plain/compressed bodies or move letters to an external archive without atomic recovery. Compression is neither encryption nor a backup.

**Ownership/dependencies:** S2 owns `CoverLetterSection.tsx`, its adapter, `cover_letters.go` reads/writes and the narrow retention migration in `internal/storage/sqlite.go`. Coordinate with S6 upgrade tests and existing deletion/history owners; load durable-state-integrity guidance before implementation. Existing records default active, with no body rewrite. Include the archive filter in the prior-letter picker contract before parallel UI work begins. Keep one writer and no retention scheduler.

**Acceptance:** Through the real app, save more than 30 synthetic letters and reach an older one; archive an unused letter, restart the same executable/workspace, find it in the archive, inspect identical text/source identity, copy it to a new draft, and restore it. Refuse archival/deletion that would silently replace effective selection or break history. Confirm cancel and failed write leave all text/associations intact. Explicitly delete an unused draft and verify referenced letters remain. Upgrade a pre-retention workspace with letters and selection/history intact on each qualified OS. If compression is later selected, additionally require byte-identical round trips, interrupted-write recovery, corrupt-payload refusal without overwriting the original, and measured net space savings before making storage claims.
